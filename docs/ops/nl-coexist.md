# Заметки: сосуществование на exit-ноде

> Для операторов и self-host. Клиентам XENO не требуется — см. [../README.md](../README.md).

На одной VPS могут жить **несколько независимых стеков**. Продукт XENO.net обязан быть **аддитивным**: ставить свои unit’ы и конфиги, не затирая чужие.

## Правила

1. Не останавливать и не перезаписывать сторонние panel/bot/service на той же машине.  
2. Свой relay/hop — отдельный systemd unit и отдельный JSON конфиг.  
3. Клиентов продукта добавлять только в **свой** inbound (через API или sync), не в чужие.  
4. UFW: открывать только нужные порты продукта; hop — по возможности только с IP entry-ноды.  
5. Секреты и реальные IP — в `secrets/` и `inventory/hosts.local.env`, не в git.

## Типичное разделение (логическое)

| Компонент | Назначение |
|-----------|------------|
| Сторонняя панель 3x-ui | Свои inbound’ы — не трогаем |
| `xeno-relay` | Внутренний hop каскада |
| `xenonet-bot` / `xenonet-sub` | Продуктовый бот и HTTPS-подписка |
| Опциональный HY2 | Может быть выключен (parked) |

Конкретные пути и порты чужих сервисов в публичный репозиторий **не** выкладываем.
